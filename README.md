# Rent Finder: باحث إيجارات شرق الرياض (متعدد المنصات)

أداة بحث **عند الطلب** تعمل بالكامل على GitHub ومن الجوال. تضغط **Run workflow**، تختار الفلاتر والمنصات، فتجمع الأداة نتائج هذا البحث فقط وتعرضها كجدول HTML فيه معلومات العقار والروابط، مع ملف Excel. لا جدولة ولا تشغيل تلقائي ولا أرشيف متراكم.

## المنصات المدعومة

| المنصة | الحالة | ملاحظات |
|---|---|---|
| **بيوت** (bayut.sa) | بنيتها مفحوصة | شقق واستراحات، سنوي وشهري |
| **عقار** (sa.aqar.fm) | صيغة النصوص والترقيم مفحوصة | شقق واستراحات وشاليهات، سنوي فقط. رابط الاستراحات والشاليهات تجرّب الأداة صيغتين له لأني لم أؤكد الصحيحة |
| **وصلت** (wasalt.sa) | جزئية | الشقق فقط. تفحص القائمة الوطنية وتُبقي ما يخص شرق الرياض، فهي أبطأ وأقل نتائج لكل صفحة |
| **حراج** (haraj.com.sa) | best-effort | تستخدم صفحة البحث العامة بالوسوم؛ لا تُقبل إعلانات البيع أو الإعلانات التي لا تعرض سعراً وفترة إيجار واضحة |
| **ديل** (dealapp.sa) | best-effort | أضيف محول HTML وعزل للأخطاء، لكن الموقع لم يرسل HTML قابلاً للتحقق في آخر فحص؛ لا تُعرض نتائج حتى ينجح الفحص |
| حراج، ديل، بروبرتي فايندر | **غير مدعومة** | بروبرتي فايندر لم تُضف بعد |

كل منصة تعمل باستقلال: إن حُجبت إحداها تكمل الأخريات، وتظهر حالة كل منصة أعلى صفحة النتائج. والإعلان نفسه المنشور في أكثر من منصة يظهر مرة واحدة مع روابط المنصات الأخرى (يُعتبر مكرراً إذا تطابق الحي والسعر والمساحة).

│   ├── config.py                     ← rentfinder/config.py
│   ├── sites.py                      ← rentfinder/sites.py

│   ├── search.py                     ← rentfinder/search.py

| الملف | وظيفته |
|---|---|
| `.github/workflows/search.yml` | نموذج التشغيل (الفلاتر) وخطوات GitHub، بلا جدولة |
| `rentfinder/config.py` | قراءة الفلاتر والتحقق منها، الثوابت، السجل (logging) |
| `rentfinder/sites.py` | تعريف كل منصة: روابط البحث، رابط الإعلان، أنماط السعر والحي |
| `rentfinder/parser.py` | تحليل HTML بلا إنترنت |
| `rentfinder/search.py` | الجلب وإعادة المحاولة وفحص المنصات والفلترة ودمج المكرر |
| `rentfinder/report.py` | بناء صفحة HTML وملف CSV وملخص التشغيل |
| `rentfinder/templates/report.html` | قالب الصفحة (فلاتر قابلة للتعديل داخل الصفحة) |
| `rentfinder/__main__.py` | نقطة التشغيل `python -m rentfinder` |
| `tests/test_parser.py` | 35 اختباراً تعمل قبل كل بحث |

## التركيب من الجوال (مرة واحدة)

1. **أنشئ مستودعاً** على github.com، واجعله **Public** (النشر المجاني عبر Pages يتطلب ذلك).
2. **أنشئ كل ملف**: Add file ← Create new file. اكتب **المسار كاملاً** في خانة الاسم (مثل `rentfinder/templates/report.html`، والشرطة المائلة تنشئ المجلد تلقائياً)، والصق المحتوى، ثم Commit changes. كرر لكل الملفات الثلاثة عشر.
   - ملف `.gitignore` و`.github/workflows/search.yml` يبدآن بنقطة، اكتبهما كما هما.
3. **فعّل النشر**: Settings ← Pages ← Source ← اختر **GitHub Actions**.
4. تأكد أن Actions مفعّلة: Settings ← Actions ← General.

## تشغيل بحث (كل مرة)

1. افتح المستودع ← تبويب **Actions** ← اختر **search** ← **Run workflow**. (من متصفح الجوال فعّل «Desktop site» إن لم يظهر الزر.)
2. عدّل الفلاتر:

| الحقل | المعنى | مثال |
|---|---|---|
| أقصى إيجار سنوي | الشهري يُضرب في 12 | `40000` |
| أدنى إيجار سنوي | | `15000` |
| نوع الوحدة | الكل / شقق / استراحات / شاليهات / مخيمات | `استراحات` |
| فترة الإيجار | الكل / سنوي / شهري | `سنوي` |
| المنصات | الكل / بيوت / عقار / وصلت / حراج / ديل | `عقار` |
| الأحياء | اختياري، بفاصلة، مطابقة جزئية | `الرمال، النسيم` |
| كلمات العنوان | يجب أن تظهر كلها | `مفروش، مسبح` |
| أدنى مساحة | بالمتر، الإعلان بلا مساحة يُستبعد | `100` |
| أُضيف خلال (أيام) | 0 = بدون. يفتح صفحة كل إعلان فيبطّئ البحث | `7` |
| أقصى صفحات لكل فئة | حوالي 25 إعلاناً للصفحة | `25` |

3. اضغط **Run workflow** وانتظر. **داخل صفحة التشغيل** سترى جدولاً بأول 30 نتيجة مع الروابط (قسم Summary)، وتحته رابط **الصفحة الكاملة** بفلاتر تفاعلية وتنزيل Excel.

الصفحة الكاملة تُستبدل بنتائج كل بحث جديد، ولا يُخزَّن شيء في المستودع، فلا يكبر حجمه أبداً.

ملاحظات: أسماء أحياء وصلت بالإنجليزية (مثل Al Sulay)، فاكتب الحي بالإنجليزية إن أردت منها. حراج وديل يعتمدان على HTML العام فقط، ولا توجد مفاتيح API أو جلسات دخول في المشروع. المنصات التي لا تناسبها الفلاتر (عقار مع «شهري» مثلاً) تُتجاوز وتظهر «غير مطلوبة».

## الفلاتر داخل الصفحة

بعد ظهور النتائج تضيّق أكثر دون إعادة البحث: المنصة، النوع، أدنى/أقصى سعر، الحي، الترتيب، بحث بالعنوان، إخفاء الأسعار المشكوك فيها. لتوسيع النطاق أعد البحث من Actions.

## ما يعنيه كل عمود

- **الإيجار السنوي**: الشهري × 12، ويظهر سعره الشهري تحته.
- **آخر زيارة**: التاريخ المطبوع على بطاقة الإعلان في بيوت فقط، وليس تاريخ النشر.
- **الإضافة**: تاريخ النشر من صفحة الإعلان، ويظهر عند استخدام فلتر «أُضيف خلال». **لم أتحقق من قراءته على المواقع الحقيقية**؛ إن لم يُقرأ يظهر «غير معروف» وتبقى الإعلانات في النتائج مع تحذير في السجل. تقرأ الأداة أيضاً صيغ «منذ يومين» و«3 days ago».
- **سعر مشكوك**: إيجار سنوي أقل من 6000 ريال، غالباً خطأ إدخال.

## الاحترافية والأداء

- **السجل (log)**: كل خطوة بمستوى (INFO/WARNING/ERROR) في الشاشة وفي `logs/run.log` (Artifact باسم `log` يُحذف بعد 3 أيام). أقسام السجل قابلة للطي، وتحذيرات الحجب تظهر كشريط في صفحة التشغيل. للتفصيل الكامل: `RENTFINDER_VERBOSE=1`.
- **المساحة**: لا commits ولا قاعدة بيانات؛ حزمة الصفحة تُحذف بعد يوم؛ لقطات التشخيص أقصاها 4 ملفات صغيرة.
- **السرعة**: حجب الصور والخطوط، تخزين المتصفح مؤقتاً، إيقاف الفئة عند انتهاء النتائج أو تكرارها، وتجاوز الفئات غير المطلوبة.
- **الأمان**: مدخلاتك متغيرات بيئة لا أوامر shell، وصلاحيات الـ workflow أدنى ما يلزم، والصفحة بلا سكربتات خارجية.
- **المتانة**: إعادة محاولة تدريجية، عزل كل منصة عن الأخرى، قاطع بعد صفحتين فاشلتين متتاليتين، حد زمني 40 دقيقة ينشر ما جُمع مع تنبيه «نتائج جزئية»، وتأخير 2 إلى 4 ثوانٍ بين الصفحات.
- **الاختبارات**: `python -m unittest tests.test_parser` تعمل قبل كل بحث، فإن فشلت لا يبدأ البحث.

## إذا فشل التشغيل

- **«لم يُقرأ أي إعلان»** أو منصة بحالة «محجوبة؟»: غالباً حجب الموقع عناوين خوادم GitHub. افتح التشغيل ← Artifacts ← `log` وأرسل لي محتوى `debug`. هذا أرجح خلل، ولم أستطع اختباره على المواقع الحقيقية.
- **منصة بحالة «لا إعلانات»**: ربما رابط البحث أو بنية الصفحة تغيّرت. أرسل لي رابط صفحة النتائج الحالية من تلك المنصة.
- **إدخال خاطئ**: يتوقف التشغيل فوراً برسالة عربية تحدد الحقل.
- **النتائج قليلة**: ارفع «أقصى صفحات» أو وسّع السعر.

## إضافة منصة جديدة

أضف كائن `Site` في `rentfinder/sites.py` (روابط البحث، نمط رابط الإعلان، نمط السعر والحي)، وسجّل مفتاحها في `SITES` وفي `SOURCE_KEYS` و`SOURCE_ALIASES` داخل `config.py`. بقية الأداة تعمل كما هي.

## تشغيل محلي (اختياري، لمن لديه حاسوب)

```
pip install -r requirements.txt
python -m playwright install chromium
INPUT_MAX_PRICE=40000 INPUT_TYPES=شقق INPUT_SOURCES=عقار python -m rentfinder
```
ثم افتح `site/index.html`.

## صفحة البحث الموحدة

يوفر المشروع الآن صفحة واحدة تفاعلية عبر `app.py`. الصفحة نفسها تحتوي الفلاتر والبحث والنتائج، بينما يبقى Playwright على الخادم ولا تُرسل أي مفاتيح أو جلسات إلى المتصفح.

للتشغيل المحلي:

```
pip install -r requirements.txt
python -m playwright install chromium
python app.py
```

ثم افتح `http://localhost:8000`. للنشر على Render: أنشئ Web Service من هذا المستودع، واختر Docker؛ ملف `render.yaml` و`Dockerfile` يجهزان الخدمة تلقائياً.

## ملاحظة

للاستخدام الشخصي فقط وبوتيرة هادئة. راجع شروط استخدام كل منصة قبل رفع حجم البحث. لا يحاول المشروع تجاوز تسجيل الدخول أو CAPTCHA أو الحجب، وقد تظهر منصة بحالة «محجوبة» بدلاً من النتائج.
